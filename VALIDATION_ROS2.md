# Проверка интеграции ROS 2, 29.09.2026

Основа — `Tactical-Inventor/LCT-2026.NIIstovye`, коммит
`88debe621e931f0233cfa77b3e0a2117b1d2ae73`. Рабочая ветка — `codex/ros2-humble`.
Использован алгоритм из этого репозитория. Из его исходных модулей изменён только
`io.py`: декодирование готового сообщения выделено в публичную функцию, добавлено
чтение исходных CDR-байтов. Остальные изменения — ROS-пакет, Docker, проверки и документация.

## Предварительная проверка на Windows

- **22 теста прошли**, один модуль нативных ROS-тестов пропущен: `python -m pytest tests -q`.
- Проверены организованные облака с padding между строками, little/big endian,
  XYZ/ring, точность float64, невалидные координаты, строгий JSON, смена источника
  и временные разрывы, составная DB3-запись и порядок timestamp.
- На **150 последовательных реальных кадрах** `cloud_with_fake_obj` сравнивались
  два независимых `StreamProcessor`: прежний файловый вход и новый адаптер
  сообщения. Координаты, ring, статусы, треки, расстояния и остальные поля JSON
  совпали точно; из сравнения исключено только время выполнения. В выборке есть
  `CLEAR`, `CAUTION` и `BLOCKED`.
- На тех же 150 кадрах проведено сравнение с исходными NumPy 2.4.6,
  SciPy 1.17.1 и Numba 0.67.0. В обоих окружениях: 1 `CLEAR`, 81 `CAUTION`,
  68 `BLOCKED`; первый `BLOCKED` — кадр 82. Статусы, ID подтверждённых
  препятствий, число треков и расстояния совпали. Численные координаты некоторых
  треков отличаются между версиями библиотек; полная численная эквивалентность
  разных окружений и качество на всём датасете не утверждаются.
- Проверка выполнялась на Windows / **Python 3.11.4**, с версиями библиотек,
  выбранными для Humble: NumPy 1.26.4, SciPy 1.15.3, Numba 0.61.2, rosbags 0.10.11.
  Это проверка библиотек и адаптера, а не запуск ROS 2 под Linux.
- Для всех зависимостей загружены готовые Linux x86_64 / CPython 3.10 wheels;
  разрешение зависимостей успешно, `pip check` не обнаружил конфликтов.
- Python-пакет успешно собран в wheel. В нём проверены обе ноды, все модули
  алгоритма, ament resource marker, `package.xml`, launch-файл и entry points.
- Проверены синтаксис Python 3.10, XML, YAML workflow, JSON-инструкции Dockerfile,
  `bash -n` для entrypoint, прежний `run.py --help` и `git diff --check`.

Первоначально проверенный SciPy 1.14.1 завершался ошибкой NNLS на реальной записи.
В итоговом `requirements-humble.txt` используется 1.15.3, на которой прогон завершился.
Предупреждения SLSQP о промежуточном выходе за границы и последующем ограничении
значений не прерывали обработку; они не скрывались.

## Нативная проверка в Docker

После установки Docker Desktop и запуска Linux-движка через WSL 2 собраны
`obstacle_detector:humble-test` и `obstacle_detector:humble` для `linux/amd64`.
В контейнере подтверждены **Ubuntu 22.04.5 LTS, ROS 2 Humble, Python 3.10.12**.
Базовый образ: `ros:humble-ros-base-jammy`, digest
`sha256:1813d3c85d7f96ff7d3012d865204583255740182db5d0065f8f8cd029a83138`.

**Все 30 тестов прошли за 6,65 с**, без пропусков, включая 8 нативных проверок:
сериализация CDR
float32/float64, reliable/best_effort подписки, ошибки и восстановление обработчика,
JSONL, поздний подписчик результата, ожидание подтверждения последнего кадра,
полный launch на DB3 и NPZ и ненулевой exit code при неверном входе.

Первый запуск выявил отсутствие `rail_config.json` в установленном пакете.
Исправлены исключение в `.dockerignore` и `package_data` в `setup.py`;
после исправления повторная сборка и весь комплект тестов завершились успешно.

Через `ros2 launch` в runtime-образе обработаны **150 кадров** реальной записи
`cloud_with_fake_obj_0.db3`. В графе подтверждены `/lidar_loader`,
`/obstacle_processor`, входной `PointCloud2` и три выходных топика.
В JSONL записаны ровно 150 последовательных результатов, все с
`processing_ok: true`; обе ноды завершились штатно, код launch — 0.
Распределение: **1 CLEAR, 81 CAUTION, 68 BLOCKED**; первый BLOCKED — индекс 82.
Timestamp/frame_id, статусы, `path_clear`, `blocking_ids`, `distance_m`
и количество треков совпали с предварительным прогоном на Windows на каждом кадре.
Полная численная эквивалентность всех координат между платформами не проверялась.
Это проверка запуска и передачи данных, а не оценка качества на всём датасете.

```bash
docker build --target test -t obstacle_detector:humble-test .
docker build -t obstacle_detector:humble .
```

GitHub Actions выполняет эти команды и сохраняет образ как скачиваемый артефакт
**после успешного запуска workflow**. В этой локальной сессии workflow не запускался.

## Повторение проверки на реальной записи

Исходная запись не включается в репозиторий. Из корня проекта:

```bash
python -m tests.check_recording /path/to/recording.db3 --frames 150 --output /tmp/parity.json
```

Этот скрипт проверяет последовательную передачу данных через адаптер без ROS.
Он не заменяет DDS-тесты или оценку качества детекции на полном датасете.
