# Obstacle_detector

Обнаружение препятствий на железнодорожном пути по последовательности облаков
точек LiDAR. Решение строит маршрут и габарит, оценивает движение, сопровождает
объекты и возвращает статус каждого кадра. 
## 1. Быстрый старт в Docker

Docker-образ содержит все зависимости алгоритма и видео, включая `imageio-ffmpeg`,
шрифты с кириллицей и всё необходимое для сборки и запуска. Права администратора,
установленный ROS, GPU и Open3D не нужны. Команды выполняются из корня проекта.

Собрать образ:
```powershell
docker build -t obstacle_detector .
```
Полный пайплайн с видео. Папка с записью монтируется только для чтения,
папка для результатов — на запись:

```powershel
docker run --rm `
  -v D:\input:/data:ro `
  -v D:\output:/output `
  obstacle_detector `
  run.py /data/example.db3 `
      --visualize `
      --output-dir /output/recording `
      --workers 4
```
| Часть команды | Назначение |
|--------------|------------|
| `-v D:\input:/data:ro` | Монтировать папку `D:\input` с вашего ПК как `/data` внутри контейнера (только чтение, защита от записи) |
| `-v D:\output:/output` | Монтировать папку `D:\output` с вашего ПК как `/output` внутри контейнера (чтение и запись) |
| `obstacle_detector` | Имя Docker-образа для запуска |
| `run.py /data/example.db3` | Запустить скрипт `run.py` с файлом `/data/example.db3` (путь внутри контейнера) |
| `--visualize` | Включить создание видео с визуализацией |
| `--output-dir /output/recording` | Сохранить результаты в папку `/output/recording` внутри контейнера |
| `--workers 4` | Использовать 4 процесса для параллельной отрисовки кадров |

До запуска:
```text
D:\
 ├── input\
 │    └── example_first_10.db3   <-- Ваш исходный файл .db3 или папка с записью
 └── output\                     <-- Пустая папка (или не существует)
```
После успешного завершения:
```text
D:\
 ├── input\
 │    └── example_first_10.db3   <-- Файл не изменился (защищён флагом :ro)
 └── output\
      └── recording\             <-- Папка создана автоматически скриптом
           ├── frames.csv        <-- Статус и данные по каждому кадру
           ├── summary.json      <-- Итоговая сводка обработки
           ├── video.mp4         <-- Визуализация (если был флаг --visualize)
           └── preview.png       <-- Превью первого кадра с препятствием
```
Для каждого запуска выбирайте новую или пустую выходную папку. Готовые
результаты скрипт не перезаписывает.


## Выходные файлы

| Файл | Содержимое |
|---|---|
| `frames.csv` | Статус, расстояние, ID объектов, оценка перемещения и время обработки каждого кадра |
| `summary.json` | Источник, число кадров, распределение статусов, настройки и общее время обработки |
| `video.mp4` | При `--visualize`: все обработанные кадры, 1920×1080, H.264 |
| `preview.png` | При `--visualize`: первое препятствие; при его отсутствии первое предупреждение, иначе первый кадр |

`summary.json` с `complete: true` появляется после успешного завершения
обработки и, если включена визуализация, записи видео.
`elapsed_ms` в CSV — время работы алгоритма без чтения и отрисовки.

Видео воспроизводится с постоянной частотой `--fps` (по умолчанию 10 кадров/с).
Его шкала времени равна `frame_idx / fps`; исходный `timestamp_ns` сохраняется
в CSV. Перед визуализацией облака читаются для выбора общей шкалы вида сверху.
Синий участок маршрута соответствует оценке дальности видимых рельсов,
оранжевое продолжение — прогнозу. Пунктирные рамки обозначают прогнозируемое
положение объектов. Отрисовка использует готовые результаты обработки.


## Настройки

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `--output-dir` | `result` | Папка сохранения результатов |
| `--topic` | Автоматически | Топик PointCloud2 |
| `--visualize` | Выключен | Сохранить видео или изображение |
| `--threads` | `3` | Число потоков Numba для обработки кадра |
| `--workers` | `3` | Число процессов отрисовки, от 1 до 8 |
| `--fps` | `10` | Частота воспроизведения видео; не меняет обработку |
| `--max-frames` | `0` | Обработать первые N кадров; 0 — всю запись |
| `--rise-m` | `0.10` | Порог возвышения над поверхностью пути, м |
| `--min-unique` | `3` | Минимальное число различных точек группы |
| `--self-return-m` | `2.5` | Радиус исключения отражений от крепления лидара, м |
| `--font`, `--font-bold` | Системные | Пути к обычному и полужирному TTF; задаются вместе |
| `--help`, `--version` | — | Справка или версия |
