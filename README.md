# Obstacle Detector — инструкция по запуску и проверке

Решение обнаруживает препятствия на железнодорожном пути по облакам точек LiDAR: строит маршрут и габарит, оценивает движение, сопровождает объекты и выдаёт решение для каждого кадра.

Инструкция предназначена для проверки на собственных данных. Имена файлов и пути в примерах условные: замените их на соответствующие пути в своей системе.

Доступны два режима:

| Режим | Назначение | Результат |
|---|---|---|
| ROS 2 | Загрузка облаков и обработка отдельными нодами с передачей данных через ROS-топики | Сообщения в топиках и, при указании пути, файл JSONL |
| Файловая обработка с визуализацией | Обработка записи тем же алгоритмом с сохранением наглядного представления | CSV, итоговая сводка и видео MP4 либо изображение PNG |

## 1. Окружение и подготовка

Docker-образ использует **Ubuntu 22.04, ROS 2 Humble и Python 3.10**. Сборка и запуск проверены для архитектуры `linux/amd64`.

На компьютере проверяющего необходим работающий Docker с Linux-контейнерами. Для Windows используется Docker Desktop с WSL 2 и включённой виртуализацией. ROS 2, Python, библиотеки алгоритма, средства записи видео и шрифты входят в образ; отдельная установка этих зависимостей на хосте не требуется. Обработка выполняется на CPU.

Распакуйте исходный код целиком, включая служебные файлы. Перейдите в каталог, содержащий `Dockerfile`, `run.py`, `package.xml` и папку `obstacle_detector_ros`. Команды сборки выполняются из этого каталога.

В Windows приведённые команды выполняются в **PowerShell**. В Linux используется **Bash**. Выберите соответствующие примеры и выполняйте их последовательно в одном терминале, чтобы сохранить значения переменных.

## 2. Входные данные

| Вход | Требования |
|---|---|
| Файл `.db3` | Запись ROS 2 в SQLite с сообщениями `sensor_msgs/msg/PointCloud2` в сериализации CDR |
| Папка записи | Файлы `.db3`, являющиеся частями одной последовательной записи; независимые записи обрабатываются отдельными запусками |
| Файл `.npy` | Одно облако: числовой массив XYZ формы `(N, 3)` |
| Файл `.npz` | Одно облако: массив `xyz` формы `(N, 3)` и необязательный целочисленный массив `ring` длины N; для ROS-загрузчика значения `ring` — от 0 до 65535 |

Облака должны содержать координаты `x`, `y`, `z` в метрах. Ожидаемая ориентация: **вперёд — −Y, вверх — +Z**. При другой ориентации координаты необходимо преобразовать до подачи в алгоритм. Изменение имени `frame_id` само по себе координаты не преобразует.

Для последовательной обработки используйте кадры одного источника в хронологическом порядке. Временные правила сопровождения рассчитаны на поток около 10 Гц. В ROS-режиме разрыв времени более 0,25 с, возврат времени назад или смена `frame_id` сбрасывают накопленное состояние; порог разрыва задаётся параметром `max_gap_sec`.

Если запись содержит несколько топиков `PointCloud2`, укажите нужный явно: `bag_topic:=/имя_топика` для ROS-запуска или `--topic /имя_топика` для файлового режима. При единственном подходящем топике выбор автоматический.

## 3. Получение Docker-образа

### Сборка из исходного кода

```text
docker build -t obstacle_detector:humble .
```

При первой сборке требуется доступ к сети для загрузки базового образа и зависимостей.

### Загрузка переданного образа

Если вместе с решением предоставлен образ в архиве `.tar`, его можно загрузить вместо сборки. Подставьте фактический путь к архиву:

```text
docker load -i "obstacle_detector_humble.tar"
```

В командах далее используется тег `obstacle_detector:humble`. Проверьте наличие образа:

```text
docker image ls obstacle_detector:humble
docker run --rm obstacle_detector:humble ros2 pkg executables obstacle_detector_ros
```

В списке исполняемых компонентов должны присутствовать `lidar_loader` и `obstacle_processor`.

## 4. Подключение данных и папки результатов

Подготовьте каталог с входными данными и создайте отдельную папку результатов для текущей проверки. В примерах исходный файл называется `recording.db3`.

### Linux / Bash

Замените `/absolute/path/to/input` на абсолютный путь к каталогу с вашими данными:

```bash
cloud_dir="/absolute/path/to/input"
result_dir="$PWD/output/check-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$result_dir"
```

### Windows / PowerShell

Замените `D:\input` на путь к каталогу с вашими данными:

```powershell
$cloudDir = "D:\input"
$resultDir = Join-Path (Get-Location) ("output\check-" + (Get-Date -Format "yyyyMMdd-HHmmss"))
New-Item -ItemType Directory -Path $resultDir | Out-Null
```

В следующих командах каталог данных доступен внутри контейнера как `/data` только для чтения, каталог результатов — как `/output` для записи. Поэтому файл `recording.db3` из входного каталога указывается в команде как `/data/recording.db3`.

Для каждого повторного запуска создавайте новую папку результатов. ROS-режим требует нового файла JSONL; файловый режим требует новой или пустой папки назначения.

## 5. Загрузка и обработка через ROS 2

Запуск выполняет две ноды:

- `lidar_loader` читает входные облака и публикует `sensor_msgs/msg/PointCloud2` в `/lidar_points`.
- `obstacle_processor` получает облака, выполняет анализ и публикует результаты.

Загрузчик передаёт следующий кадр после подтверждения обработки предыдущего. По завершении записи обе ноды автоматически останавливаются.

### Linux / Bash

```bash
docker run --rm --name obstacle-detector-check -v "${cloud_dir}:/data:ro" -v "${result_dir}:/output" obstacle_detector:humble ros2 launch obstacle_detector_ros pipeline.launch.py input:=/data/recording.db3 output_jsonl:=/output/ros2_results.jsonl max_frames:=0
```

### Windows / PowerShell

```powershell
docker run --rm --name obstacle-detector-check -v "${cloudDir}:/data:ro" -v "${resultDir}:/output" obstacle_detector:humble ros2 launch obstacle_detector_ros pipeline.launch.py input:=/data/recording.db3 output_jsonl:=/output/ros2_results.jsonl max_frames:=0
```

Каждая команда запуска приведена одной строкой. `max_frames:=0` означает обработку всей записи. Для короткой проверки задайте нужное количество кадров, например `max_frames:=100`. Для папки записи или отдельного NPY/NPZ замените значение `input` соответствующим путём внутри `/data`.



| Топик | Тип сообщения | Содержимое |
|---|---|---|
| `/lidar_points` | `sensor_msgs/msg/PointCloud2` | Входное облако |
| `/obstacle_detector/result` | `std_msgs/msg/String` | Результат кадра в формате JSON |
| `/obstacle_detector/corridor` | `sensor_msgs/msg/PointCloud2` | Точки выбранного коридора |
| `/obstacle_detector/obstacles` | `sensor_msgs/msg/PointCloud2` | Наблюдаемые точки подтверждённых препятствий текущего кадра |

Результаты также сохраняются на хосте в `ros2_results.jsonl`: одна строка — один JSON-объект для одного кадра. Основные поля: `frame_index`, `header`, `processing_ok`, `status`, `path_clear`, `distance_m`, `blocking_ids` и `tracks`. Индексы кадров начинаются с нуля. `distance_m` задаётся в метрах; `null` означает отсутствие определённого значения.

Для успешного прогона проверьте сообщение `Completed N clouds`, штатное завершение процессов и код возврата 0. Число строк JSONL должно соответствовать числу обработанных кадров, а `processing_ok` каждой строки — быть `true`. Код последней команды проверяется через `echo $?` в Bash или `$LASTEXITCODE` в PowerShell сразу после завершения `docker run`.

Штатная остановка обработчика через `SIGINT` после завершения загрузчика допустима. При ошибке обработки кадра результат содержит `processing_ok: false` и поле `error`; запуск завершается с ненулевым кодом. Первичная компиляция Numba может увеличить время до первого результата.

## 6. Наглядная визуализация

Для получения видео запустите файловый режим `run.py` с флагом `--visualize`. Он повторно обрабатывает исходные облака тем же алгоритмом и сохраняет визуализацию; файл JSONL предыдущего запуска для этого не используется. ROS-запуск из раздела 5 сохраняет результаты в топики и JSONL, а MP4 создаётся командой ниже.

### Linux / Bash

```bash
docker run --rm -v "${cloud_dir}:/data:ro" -v "${result_dir}:/output" obstacle_detector:humble run.py /data/recording.db3 --visualize --max-frames 0 --fps 10 --output-dir /output/visualization
```

### Windows / PowerShell

```powershell
docker run --rm -v "${cloudDir}:/data:ro" -v "${resultDir}:/output" obstacle_detector:humble run.py /data/recording.db3 --visualize --max-frames 0 --fps 10 --output-dir /output/visualization
```

Для короткой проверки замените `--max-frames 0` на ограничение числа кадров. Дождитесь сообщения `Complete: /output/visualization` и успешного завершения команды. Результаты находятся в подпапке `visualization` выбранного каталога результатов.

| Файл | Содержимое |
|---|---|
| `frames.csv` | Статус, расстояние, идентификаторы объектов и время обработки каждого кадра |
| `summary.json` | Параметры запуска, число кадров, распределение статусов и итоговая сводка |
| `video.mp4` | Для записи DB3: видео с облаком точек, видом сверху, объектами и статусом; 1920×1080, H.264 |
| `preview.png` | Для видео: кадр с приоритетом подтверждённого препятствия, затем предупреждения, иначе первый кадр |
| `frame.png` | Для одиночного NPY/NPZ: изображение результата вместо видео |

Успешный результат содержит `summary.json` с `complete: true`. Частота `--fps` определяет воспроизведение видео; например, 100 кадров при 10 кадрах/с дают 10 секунд видео. Длительность вычислений зависит от входных данных и компьютера. Перед отрисовкой запись дополнительно читается для выбора общей шкалы вида сверху.

Откройте `video.mp4` обычным видеоплеером. В PowerShell после завершения обработки:

```powershell
Invoke-Item -LiteralPath "$resultDir\visualization\video.mp4"
```

## 7. Настройки и интерпретация результатов

Основные параметры запуска:

| Назначение | ROS 2 | Файловый режим |
|---|---|---|
| Вход | `input:=/data/recording.db3` | `/data/recording.db3` после `run.py` |
| Лимит кадров, 0 — вся запись | `max_frames:=0` | `--max-frames 0` |
| Выбор топика в DB3 | `bag_topic:=/имя_топика` | `--topic /имя_топика` |
| Сохранение результатов | `output_jsonl:=/output/ros2_results.jsonl` | `--output-dir /output/visualization` |
| Потоки обработки, по умолчанию 3 | `threads:=3` | `--threads 3` |
| Частота подачи / воспроизведения | `rate_hz:=10.0` — максимум подачи облаков | `--fps 10` — частота видео |
| Параллельная отрисовка | — | `--workers 3`, допустимо от 1 до 8 |

`rate_hz` ограничивает подачу облаков и не гарантирует обработку в реальном времени. `--fps` меняет частоту видео, сохраняя порядок обработки кадров. Полный список параметров доступен через справку:

```text
docker run --rm obstacle_detector:humble ros2 launch obstacle_detector_ros pipeline.launch.py --show-args
docker run --rm obstacle_detector:humble run.py --help
```

Интерпретация `status`:

- `CLEAR` — алгоритм оценивает габарит как свободный.
- `CAUTION` — предупреждение либо недостаточно данных для уверенного решения.
- `BLOCKED` — алгоритм подтвердил препятствие, блокирующее проезд в габарите.

`processing_ok: true` означает успешное выполнение обработки кадра. Вывод о проезде определяется полем `status`; пустое облако `/obstacle_detector/obstacles` само по себе не заменяет этот вывод. Для оценки качества сопоставляйте решения с разметкой собственных проверочных данных.

## 8. Автоматическая проверка и материалы

Из корня исходного кода можно собрать тестовый образ и выполнить комплект проверок, включая обмен сообщениями ROS 2:

```text
docker build --target test -t obstacle_detector:humble-test .
```

Ошибка теста прерывает сборку. Состав и результаты выполненных проверок описаны в `VALIDATION_ROS2.md` в корне исходного кода. Расширенная инструкция `ROS2.md` содержит параметры нод и подключение внешнего источника `PointCloud2`.
